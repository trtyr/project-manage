# 售前工作方法论

> 示例公司项目交付售前（Presales）岗位的标准工作方法与阶段模板。供新员工
> 入职培训、阶段模板导入参考、以及阶段推进过程中的自检使用。

## 售前定位

> 售前是销售和产研之间的**翻译官**——客户痛点与示例公司能力双向翻译。

售前向上承接销售线索，向下连接产研交付，是项目从「销售拿单」到「交付落地」
之间的关键纽带。核心职责：

- **对外**：理解客户真实痛点，把业务语言翻译成技术问题。
- **对内**：把示例公司的产品能力、技术方案、交付节奏翻译成客户能感知的价值。
- **贯穿**：在签单前负责可信度与技术兜底，在签单后为交付团队铺路。

---

## 七大标准阶段

一个完整的售前项目，按时间顺序通常划分为以下 **七个阶段**。每个阶段
都有明确的输入、产出和推进目标，阶段模板可直接在 sec-tracker 中导入。

| # | 阶段名称 | 阶段描述 | 核心目标 |
|---|---------|---------|---------|
| 1 | 需求挖掘 | 线索验证，确认客户真实需求 | 识别真伪需求，定位关键决策人 |
| 2 | 技术预研 | 技术可行性评估，环境调研 | 评估能否承接，把控技术风险 |
| 3 | 方案论证 | 方案设计，技术交流 | 输出可投标的解决方案 |
| 4 | 立项审批 | 推动客户内部立项 | 把项目推到客户内部的决策流程 |
| 5 | 启动采购 | 采购流程启动，预算确认 | 确认预算来源与采购路径 |
| 6 | 商务招标 | 投标文件准备，商务谈判 | 中标并锁定合同条款 |
| 7 | 签单冲刺 | 最终技术兜底，签单闭环 | 处理最后一公里的技术与商务问题 |

### 阶段要点说明

1. **需求挖掘**——不只听客户「想要什么」，更要问「为什么」。分辨是预算
   驱动的真实需求，还是走流程的应付式询价。
2. **技术预研**——对客户业务场景、网络环境、现有防护体系做技术摸底，
   判断 PoC 可行性、识别技术风险点。
3. **方案论证**——输出《技术方案》或《解决方案》文档，与客户技术团队
   多轮交流，沉淀方案亮点与差异化优势。
4. **立项审批**——推动客户内部立项流程（OA / 预算申请 / 领导审批），
   拿到正式的内部立项编号或会议纪要。
5. **启动采购**——锁定采购方式（单一来源 / 竞争性谈判 / 公开招标），
   推进预算与采购路径落地。
6. **商务招标**——按客户要求准备投标文件（商务标 + 技术标），处理
   评标答疑、商务谈判、价格让步。
7. **签单冲刺**——最终技术兜底（答疑、POC 复测、承诺条款确认），
   完成合同签署、保证金 / 履约手续，确保签单闭环。

## 售前核心工作链

需求调研 → 技术交流 → 方案设计 → PoC 验证 → 投标技术支持 → 交付技术兜底

这是售前在「技术维度」的**核心工作流**，贯穿项目全生命周期：

```text
需求调研  →  技术交流  →  方案设计  →  PoC 验证  →  投标技术支持  →  交付技术兜底
   │            │            │            │              │                │
   ▼            ▼            ▼            ▼              ▼                ▼
听客户      与客户技术    输出方案      现场或远程      投标答疑        把客户和
痛点与      团队对齐      文档与       验证能力       评分应答        交付团队
业务目标    架构语言      技术路线      与场景匹配      商务条款        顺利交接
```

- **需求调研**：听清楚、问明白、记录到位。
- **技术交流**：用客户的语言讲技术，建立专业信任。
- **方案设计**：差异化、可落地、有亮点。
- **PoC 验证**：用现场结果回应客户疑虑，胜过任何 PPT。
- **投标技术支持**：评分项逐条应答，确保不丢分。
- **交付技术兜底**：把客户关系、技术承诺、风险点完整传递给交付团队。

## 与七大阶段的关系

| 核心工作链节点 | 主要对应阶段 | 说明 |
|--------------|------------|------|
| 需求调研 | 阶段 1、阶段 2 | 需求验证与技术预研并行 |
| 技术交流 | 阶段 3 | 方案论证的核心动作 |
| 方案设计 | 阶段 3 | 输出可投标方案 |
| PoC 验证 | 阶段 3、阶段 4 | 视客户流程决定 |
| 投标技术支持 | 阶段 5、阶段 6 | 配合商务完成投标 |
| 交付技术兜底 | 阶段 7 | 签单冲刺与交接 |

> 工作链是「技术维度」的横切主线，七阶段是「时间维度」的纵向划分。
> 二者交叉形成售前项目的完整工作视图。

## 阶段推进自检

每个阶段切换前，问自己三个问题：

1. **本阶段的产出物是否齐备？**（文档、纪要、PoC 报告、审批单据）
2. **下一阶段的输入是否清晰？**（客户对接人、决策人、时间节点）
3. **风险与未决事项是否已经显性化？**（技术风险、商务风险、合规风险）

只有三个问题都有明确答案，才能把阶段标记为「已完成」并推进下一阶段。

## 在 sec-tracker 中的使用

打开任意项目的「阶段规划」标签页，点击 **「导入七阶段模板」** 按钮：

- 项目尚无阶段时，一键导入全部 7 个标准阶段。
- 项目已有阶段时，弹窗确认后追加到阶段列表末尾（不会覆盖已有阶段）。

导入后可根据项目实际情况调整阶段名称、描述、计划时间、负责人，
以及为每个阶段关联对应的交付产物（文档 / 报告 / 链接）。
