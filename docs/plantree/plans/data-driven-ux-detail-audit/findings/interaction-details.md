# 交互细节（interaction-details）

> 走查方法：playwright 活体 + 代码比对；截图 evidence/screenshots/sweep-*.png

## I1 · 凭据遮罩按钮形态无暗示 — P3

- 位置：`AssetsTab.tsx:138-140`（`••••••` link 按钮）
- 现象：凭据列统一显示 `••••••` 超链接按钮，无凭据的资产行显示「-」；
  有/无凭据可区分，但「有几种凭据」「什么类型」完全不可见——用户必须
  点开才知道（结合 C2 结构化后此问题自然消解）
- 建议：随 C2 一并处理（凭据列显示类型 Tag 列表）

## I2 · 阶段导入模板无去重检查、无清单预览 — P2

- 位置：`PhasesTab.tsx:413-427`（「导入七阶段模板」；已有阶段时有
  Popconfirm「将追加在末尾，确认导入？」——确认弹窗存在）
- 现象：确认弹窗有了，但（a）**无重名检查**——连点两次导入就是 14 条
  重复阶段；（b）确认文案只说「追加在末尾」，不展示将插入的 7 条
  清单，用户不知道会插进什么（尤其结合 I3：模板是售前漏斗，不看
  清单根本意识不到不匹配）
- 证据：代码（importTemplateMut 直接循环 create ×7，无去重）；DB 已有
  3 阶段
- 建议：Popconfirm 换 modal.confirm，内容列出 7 条阶段名；已存在同名
  阶段时跳过并在成功提示里说明「跳过 N 条同名」
- 勘误：本条初稿误写「无确认弹窗」——目标审计指出 PhasesTab.tsx:415-419
  已有 Popconfirm，实存问题是去重与清单预览缺失

## I3 · 七阶段模板内容与项目形态错配 — P2

- 位置：`PhasesTab.tsx:66-78`（STANDARD_PHASES：需求挖掘→技术预研→
  方案论证→立项审批→启动采购→商务招标→签单冲刺）
- 现象：模板是**售前销售漏斗**；当前唯一项目是**交付型**（3 个阶段全是
  交付里程碑）——售前流程对交付项目毫无用处，导入反而污染
- 建议：模板多套化（「售前流程」/「交付流程」/自定义）；交付模板按
  当前项目的真实阶段抽象（梳理→开发→对接→验收→运营）
- 注：这是数据画像驱动的判断——单项目样本下保留「可能另有售前项目」
  的可能性，模板不应删除只应区分场景

## I4 · FileLibrary（资料库页）无上传入口 — P3

- 位置：`pages/FileLibrary.tsx`（全页无 upload 调用，grep 0 命中）
- 现象：全局资料库只能看/搜/下载，上传必须进项目→资料→文件——
  「先有项目才能传文件」的模型本身合理，但从资料库页想补传时
  是死路（无引导）
- 建议：空态/页头提示「上传请进入项目的 资料→文件」（文案级修复）；
  或提供「选择项目后上传」的快捷流（功能级，非必须）

## I5 · Board「资料」统计口径是全库文件数 — P3

- 位置：`ProjectBoard.tsx`（资料 Statistic = recentFiles?.length，
  query 是 files-all 全库）
- 现象：单项目时显示 12 恰好正确；多项目后这个数字是**所有项目的
  文件总和**，放在项目看板上会误导（「我的项目只有 3 个文件为什么
  显示 12？」）
- 证据：queryKey ['files-all'] + 探针 board-stats 输出 资料:12
- 建议：多项目出现前改为「全部资料」措辞（零成本）；或按项目过滤

## I6 · 双格式文件在阶段产物区重复堆叠 — P3

- 位置：PhasesTab 阶段产物区（SOP 梳理阶段下挂 7 个文件，其中
  md+pdf 成对出现两对）
- 现象：「SOP 梳理」产物区 7 个文件名平铺，`网络威胁告警分析 SOP.md`
  与 `.pdf` 相邻但无关联标识——与 F5 同根
- 建议：随 F5 的相似名分组方案

## I7 · 主题 Switch 的 emoji 子元素双渲染 — P3（可访问性）

- 位置：`App.tsx` 主题 Switch（checkedChildren="🌙" unCheckedChildren="☀️"）
- 现象：antd Switch 两个 children 都在 DOM 里（CSS 切换可见性），
  读屏/innerText 抓取会同时读到 🌙☀️；走查 body 文本转储已实际观察到
- 建议：antd 内部行为，优先级极低；若做无障碍深化再处理
  （aria-label="切换深浅主题" 已经通过开关上下文可推断）

## I8 · 凭据弹窗宽度对长 API Key 不换行提示 — P3

- 位置：SecretText Modal width=480 + Paragraph pre-wrap
- 现象：32 位 hex key 会换行显示（pre-wrap ✓），但 480px 弹窗在
  窄屏下已被全局 max-width 规则压缩——长 key 显示为多段；
  无「一键格式化/分组」显示（如 4 位一组）便于人工核对
- 建议：随 C2 结构化；或 key 显示按 4 组分隔（仅显示态）
