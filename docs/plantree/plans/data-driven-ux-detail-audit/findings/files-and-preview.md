# 文件与在线预览（files-and-preview）— 用户点名④

> 数据画像：12 文件 5 种 mime（pdf×5 / md×3 / docx×2 / txt×1 / xlsx×1），
> 12/12 关联阶段、0 标签、0 关联沟通。证据：evidence/data-profile.md ②

## F1 · 预览支持矩阵（5 mime 活体实测）— 基线事实

| mime | 库内数量 | 预览实现 | 活体结果 | 体验评价 |
|---|---|---|---|---|
| application/pdf | 5 | `<iframe>` 浏览器原生（FilePreview.tsx:133-139） | ✓ iframe 渲染 | 好 |
| text/markdown | 3 | 纯文本+行号（isTextType 走 text 分支） | ✓ 55 行原始源码 | **差：不渲染**（见 F2） |
| text/plain | 1 | 纯文本+行号 | ✓ 33 行 | 可（但见 F4） |
| docx | 2 | 无分支 → 兜底文案 | 「此文件类型不支持在线预览，请下载查看」 | 差（见 F3） |
| xlsx | 1 | 无分支 → 兜底文案 | 同上 | 差 |

- 证据：evidence/preview-matrix.js 输出 + 5 张截图
  evidence/screenshots/preview-*.png；后端 `/api/files/:id/preview` 为
  inline + 正确 mime（files.rs:358-387），支持面纯由前端组件决定
- 图片/html 类型代码里有分支但库内无此类文件（未实测）

## F2 · Markdown 不渲染——工作稿场景的核心缺口 — P1

- 位置：`FilePreview.tsx:8-41`（isTextType 把 md 归为纯文本）
- 现象：md 文件显示为「带行号的源码」；实测 `网络威胁告警分析 SOP.md`
  55 行里包含 **mermaid 图表块**（```mermaid graph TD），纯文本形态下
  图表语法完全不可读
- 数据含义：md 是真实工作稿格式（3 个 SOP 是 md，还有 md→pdf 双轨，
  见 F5）——「写 md、导 pdf、挂阶段」是主工作流，预览却是源码
- 建议：引入 markdown 渲染（react-markdown + remark-gfm；mermaid 可
  二期）；渲染视图与源码视图可切换（技术用户可能想看源码）

## F3 · docx/xlsx 无预览（3/12 文件「请下载」）— P2

- 位置：`FilePreview.tsx:193-200`（兜底分支）
- 现象：25% 的文件只能下载看；xlsx 是「安全运营场景需要数据集团提供的
  数据-1」——这类需求清单恰是最需要在线快速过目的
- 建议（按性价比排序）：
  1. xlsx → SheetJS（xlsx 库）前端解析渲染表格（无服务端依赖，成熟方案）
  2. docx → mammoth.js 转 HTML 预览（保真度中等，够用）
  3. 兜底文案优化：给出文件大小 + 「下载」直达按钮（现在只有文字提示，
     还要自己去找下载按钮——见 F6）

## F4 · .txt 文件内容实为 markdown（分类错位）— P3

- 证据：实测 `一体化平台日志结构样例.txt` 内容以 `# 一体化平台日志结构样例`
  `## EDR 一体化平台告警摘要日志` 开头——是 md 内容存成了 .txt
- 影响：即使 F2 做了 md 渲染，此文件按扩展名仍走纯文本分支
- 建议：F2 的渲染判定可「内容嗅探」（开头匹配 `^#{1,6}` 即按 md 渲染）；
  或上传时对 .txt 内容嗅探提示「这看起来是 markdown，改个扩展名？」

## F5 · md→pdf 双轨并存无关联 — P2（正向信号 + 缺口）

- 证据：`网络威胁告警分析 SOP`（.md + .pdf 两份）、`终端告警`
  （`_v3.md` + `分_v3.pdf` 两份）—— 工作稿/交付稿双轨是真实工作流
- 缺口：同一 SOP 的两个文件是两条独立记录，无任何关联标记；将来版本
  一多（v3/v4/v5）阶段产物区会堆积一列同名异版文件
- 建议：轻做——文件加 `alternate_file_id`（指向导出稿）或按文件名
  相似度在 UI 分组；重做——SOP 文档实体化（文档→多格式版本）。
  建议先轻做观察

## F6 · 不支持预览的兜底态没有下载按钮 — P3

- 位置：`FilePreview.tsx:196-200`（只有一行 Text 提示）
- 现象：提示「请下载查看」但弹窗内没有下载按钮，用户要关弹窗回列表找
  下载图标——多两步
- 建议：兜底分支直接放一个「下载文件」按钮（filesApi.download 现成）

## F7 · 文件命名混乱（版本后缀 + 错别字）— P3

- 证据：`_v2.0` / `_v3` / `分_v3` / `-1` 四种版本形态；`互联网暴漏面告警
  SOP 分析.md` 的「暴**漏**」为「暴露」错别字（且同名 pdf 是正确的
  「暴露面」——同一文档两个名字）
- 建议：不做强校验（内部工具）；上传时若文件名与已有文件相似度高于
  阈值，提示「已有类似文件，是否替换/关联版本？」——顺手解决 F5
